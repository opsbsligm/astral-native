# Native Deck motion

Linux can feed the existing six-axis fusion directly from the Deck's hidraw reports. The existing motion thread owns the descriptors; native discovery and reads happen outside the SDL gamepad lock. Buttons, stick mappings, controller configuration and `AC_MOTION` keep their existing contracts. No service, permission change, HID feature report or controller grab is installed.

The reader validates the opened character device with `HIDIOCGRAWINFO` (USB Valve 28de:1205), then selects only an interface producing complete 64-byte `01 00 09 40` reports with nonzero gravity. Discovery, polling and draining are bounded and nonblocking. Duplicate/backward packet counters, oversized packets and invalid reports cannot refresh motion. Counters wrap modulo 32 bits. A selected source expires after 250 ms without a new sample; the existing fusion stops reporting connected samples after its 200 ms history limit. Errors and disconnects close the descriptors, with a one-second rediscovery delay.

Native samples already use the Switch frame in G and radians/s. They bypass the SDL coordinate conversion. Native input is preferred for a directly identified Deck controller, and fills the missing sensor path of a sensorless virtual gamepad. An external controller with working SDL sensors retains its own motion source. A selected native source with no new packet does not alternate with SDL readings; when native input is unavailable, the existing SDL sensor path remains the fallback. Disabling motion or disconnecting the gamepad closes native descriptors; source transitions reset fusion integration. A read-only reader cannot enable an IMU disabled by Steam. No physical sample is invented in that case.

Protocol and scale references: [SDL 3.2.30 Steam Deck backend](https://github.com/libsdl-org/SDL/blob/release-3.2.30/src/joystick/hidapi/SDL_hidapi_steamdeck.c), [Linux hidraw API](https://docs.kernel.org/hid/hidraw.html). The original NativeDeck decoder is MIT; see `THIRD_PARTY_NOTICES.md`.

`python3 tests/deck_motion_test.py -v` exercises the actual decoder, reader and production motion loop with synthetic reports and real Unix message descriptors under ASan/UBSan. Device identity queries are instrumented. This is component validation: physical Deck report availability, aiming direction/sensitivity and the actual game's six-axis use remain unverified. `hardware_validated=false`.
